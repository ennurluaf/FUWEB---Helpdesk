Lesson 1: Trace a full-stack request

Follow one read request from the browser, through the Express route, back to JSON, and into the page.

  1. The browser starts GET /api/tickets.
  2. Express matches the collection route and reads the in-memory ticket records.
  3. The server responds with an HTTP status and JSON.
  4. Browser JavaScript renders the returned records as text.

          Lesson 6: Test the API against PostgreSQL
        
        
      
          Each test sends a real request to the Express API, which runs the
          stored procedures and functions in the helpdesk
          database. A test passes when the HTTP status and the body match the
          expected result.
        
      
        
        
          
      • 
            Tests that write data create their own tickets and remove them
            afterwards, so the sample tickets stay unchanged.
          
        • 
          
      • 
            The search test sends SQL injection strings. Because the API passes
            the keyword as a query parameter ($1), PostgreSQL
            treats it as plain text and nothing matches.
          
        • 
          
      • 
            The last check forces a database connection failure and makes sure
            the client only receives a generic error.
          
        • 
        
      

        
      
          
      CRUD procedure tester
      
          
      
            Run each test case by hand. Read, Create, Update and Close fill the
            form with the ticket that comes back.
